EigDefault

EigenValueSolvers.EigDefault — Type
EigDefault(which = :LR)
EigDefault(; which = :LR)

Direct eigen solver based on LinearAlgebra.eigen. It computes the full spectrum and then returns the nev eigenpairs selected by which (one of TARGETS). Sparse matrices are converted to dense ones first, so this solver is meant for small problems and as a reference for the iterative solvers.

Supports the generalized eigenvalue problem through gev.

source
Renamed in v0.2.0

This solver was called DefaultEig up to v0.1.2. There is no alias for the old name, so rename all uses when upgrading.

EigDefault computes the full spectrum with LinearAlgebra.eigen and then selects nev eigenpairs from it. Sparse matrices are converted to dense ones first, so this solver is meant for small problems and as a reference for the iterative solvers. It is the only solver that needs no additional package.

EigArpack

EigenValueSolvers.EigArpack — Type
EigArpack(sigma = nothing, which = :LR; kwargs...)
EigArpack(; sigma = nothing, which = :LR, kwargs...)

Iterative eigen solver based on Arpack.jl. Requires using Arpack.

sigma and which can be given positionally or as keywords, and must agree if both are given.

If sigma is given, the shift-invert method (J - sigma⋅I)⁻¹ is used and the nev eigenvalues closest to sigma are computed. which then only sets the order of the result. EigArpack(; sigma = 0.0, which = :SR) therefore gives the smallest eigenvalues only if the spectrum is positive, e.g. for a stiffness matrix. Use a slightly negative shift if it has rigid body modes. Without a shift, which selects the eigenvalues as documented in TARGETS, but ARPACK converges poorly for the smallest ones (:SM, and :SR for generalized problems), so prefer a shift for them.

For real problems, :LI/:SI throw if all eigenvalues are real, i.e. for a symmetric problem (with positive definite B if generalized), and they need 2nev ≤ n - 2.

The eigenvalues are real for symmetric problems, also for generalized ones with a shift if B is positive definite. For other real problems they are real if all computed ones are, and complex otherwise, so the element type can depend on the data.

Symmetry and definiteness are tested exactly (issymmetric, isposdef), so matrices that are symmetric only up to roundoff are treated as nonsymmetric. If B is not positive definite, B⁻¹A is solved instead, since ARPACK's generalized modes require it. This throws if B is singular, use a shift then.

Additional kwargs are forwarded to Arpack.eigs, except for nev, ritzvec and explicittransform, which are set by the solver.

Supports the generalized eigenvalue problem through gev.

source

Requires using Arpack. Extra keyword arguments given to the constructor are forwarded to Arpack.eigs, e.g.

EigArpack(-1.0, :SR; tol = 1.0e-10, maxiter = 500)

EigArnoldiMethod

EigenValueSolvers.EigArnoldiMethod — Type
EigArnoldiMethod(; sigma = nothing, which = :LR, x₀ = nothing, factorize = lu, kwargs...)

Iterative eigen solver based on ArnoldiMethod.jl. Requires using ArnoldiMethod.

If sigma is given, the shift-invert method (sigma⋅I - J)⁻¹ is used and the nev eigenvalues closest to sigma are computed. which then only sets the order of the result. Without a shift, which selects the eigenvalues as documented in TARGETS.

The shifted matrix is factorized with the factorize function. See the field documentation below for how to use a different sparse direct solver.

Additional kwargs are forwarded to ArnoldiMethod.partialschur.

Supports the generalized eigenvalue problem through gev, which always uses the shift-invert method with a shift of sigma === nothing ? 0 : sigma.

source

Requires using ArnoldiMethod. Extra keyword arguments given to the constructor are forwarded to ArnoldiMethod.partialschur, e.g.

EigArnoldiMethod(; sigma = -1.0, which = :SR, mindim = 40, maxdim = 80)

ArnoldiMethod.jl has no :SM target. Use a shift of zero instead, which computes the eigenvalues closest to the origin.

Plugging in another sparse direct solver

With a shift, most of the time in EigArnoldiMethod is spent factorizing sigma⋅I - J (or A - sigma⋅B for gev). The factorization is done by the function in the factorize field, which defaults to LinearAlgebra.lu (UMFPACK for sparse matrices). It is called as factorize(M), and its result F only has to support LinearAlgebra.ldiv!(y, F, x). To use a different solver, pass another function:

using EigenValueSolvers, ArnoldiMethod, LinearAlgebra# a Cholesky factorization, if the shifted matrix is known to be positive definiteEigArnoldiMethod(; sigma = 1.0e5, which = :SR, factorize = cholesky)

Some alternatives to UMFPACK:

packageuse case
choleskypart of LinearAlgebra, for a positive definite shifted matrix, e.g. a shift below the spectrum of a stiffness matrix
Pardiso.jlshared-memory parallel direct solver
MUMPS.jldistributed-memory (MPI) direct solver for problems that do not fit on one machine
HSL.jlMA57 for symmetric indefinite matrices, such as sigma⋅I - J with a shift inside the spectrum
LinearSolve.jlcommon interface to many of the above

Not all of these return an object that supports ldiv!. In that case write a small wrapper type that implements ldiv!(y, ::MyWrapper, x) and pass factorize = M -> MyWrapper(M). The matrix is factorized once per solver call. To reuse a factorization across calls, return a cached object from the closure.

ArnoldiMethodTransformations.jl implements the same transformations for ArnoldiMethod.partialschur directly, without this package.

EigKrylovKit

EigenValueSolvers.EigKrylovKit — Type
EigKrylovKit(; kwargs...)

Matrix-free iterative eigen solver based on KrylovKit.jl. Requires using KrylovKit.

Unlike the other solvers, J does not have to be an AbstractMatrix. Any object that supports J * x works, but then a starting vector x₀ is required. The eigenvectors are returned as a vector of vectors, use geteigenvector to access them.

Supports the generalized eigenvalue problem through gev, which requires B to be positive definite and ishermitian and isposdef to be set. A and B may be arbitrary operators there as well, again provided that x₀ is supplied.

See the fields below for the available keyword arguments.

source

Requires using KrylovKit. This is the only matrix-free solver: J can be any object that supports J * x. In that case a starting vector x₀ is required.

using EigenValueSolvers, KrylovKitsolver = EigKrylovKit(; which = :LR, ishermitian = true, x₀ = rand(n))values, vectors, converged, numops = solver(x -> A * x, 4)

The eigenvectors are then returned as a vector of vectors, so use geteigenvector to access them.

EigLOBPCG

EigenValueSolvers.EigLOBPCG — Type
EigLOBPCG(; which = :SR, tol = nothing, maxiter = 200, P = nothing, C = nothing, X₀ = nothing, kwargs...)

Iterative eigen solver based on the LOBPCG implementation of IterativeSolvers.jl. Requires using IterativeSolvers.

LOBPCG only handles symmetric or hermitian problems, with a positive definite B in the generalized case. It computes the smallest eigenvalues without factorizing the matrix. This makes it useful for large sparse problems where the shift-invert methods of EigArpack and EigArnoldiMethod run out of memory, ideally with a preconditioner P.

Because LOBPCG selects eigenvalues by algebraic value, only the targets :LR and :SR are supported, see supportedtargets.

The matrix has to be at least three times as large as the block size (nev, or the width of X₀), otherwise LOBPCG is unstable and throws. Use EigDefault for such small problems.

Two numerical caveats: a very tight tol (below roughly 1e-9) often makes the Rayleigh-Ritz step fail with a PosDefException, because the search space becomes numerically rank deficient. And without an explicit X₀, LOBPCG starts from a rand block. Its columns are all close to the all-ones vector, which is poorly conditioned, and the result depends on the global random number generator. Pass X₀ for reproducible runs.

Supports the generalized eigenvalue problem through gev.

source

Requires using IterativeSolvers. Unlike the Arnoldi-based solvers, LOBPCG computes the smallest eigenvalues without a factorization. This makes it an option when lu(K - sigma*M) does not fit in memory. Its convergence depends strongly on the preconditioner P, which is applied as ldiv!(P, x):

using EigenValueSolvers, IterativeSolvers, LinearAlgebra# an incomplete Cholesky or algebraic multigrid preconditioner belongs heresolver = EigLOBPCG(; which = :SR, P = Diagonal(diag(K)), tol = 1.0e-10, maxiter = 500)values, vectors, converged, iterations = gev(solver, K, M, 10)

Restrictions: the problem has to be symmetric or hermitian with a positive definite B, only the targets :LR and :SR are available, and the matrix must be at least three times as large as nev.

EigGenericArpack

EigenValueSolvers.EigGenericArpack — Type
EigGenericArpack(; which = :LR, kwargs...)

Iterative eigen solver based on GenericArpack.jl, a pure Julia translation of ARPACK. Requires using GenericArpack.

Compared to EigArpack, it needs no compiled ARPACK library and is not restricted to the four BLAS element types. It runs in Float32, BigFloat or any other AbstractFloat, which helps when a problem is too ill-conditioned for double precision.

It only handles symmetric or hermitian problems, so :LI and :SI are not supported, see supportedtargets. It also has no shift. Use EigArpack or EigArnoldiMethod for the shift-invert method.

Additional kwargs are forwarded to GenericArpack.symeigs.

Supports the generalized eigenvalue problem through gev, which requires B to be positive definite.

source

Requires using GenericArpack. GenericArpack.jl is a pure Julia translation of ARPACK. Compared to EigArpack, it needs no compiled library and supports element types other than the four BLAS types. Together with GenericSchur.jl for dense matrices, this allows eigenvalue computations in extended precision:

using EigenValueSolvers, GenericArpackK = big.(stiffness_matrix)values, vectors, converged, numops = EigGenericArpack(; which = :SR)(K, 5)

It only handles symmetric or hermitian problems, so :LI/:SI are not available. It also has no shift. Use EigArpack or EigArnoldiMethod for shift-invert.

Writing a new solver

A new solver is a subtype of one of the abstract types below that implements EigenValueSolvers.eigsolve and, optionally, EigenValueSolvers.geneigsolve. Both should pass the raw output of the backend through EigenValueSolvers.sortselect, so that the order and the number of returned eigenpairs match the other solvers.

If the backend does not support every entry of TARGETS, define supportedtargets for the new type. An unsupported target is then rejected when the solver is constructed, instead of returning the wrong part of the spectrum.

EigenValueSolvers.AbstractEigenSolver — Type
AbstractEigenSolver

Supertype of all eigenvalue solvers.

Every solver l::AbstractEigenSolver is callable and implements the standard eigenvalue problem J⋅x = λ⋅x

l(J, nev; kwargs...) -> (values, vectors, converged, numops)

and, if the underlying backend supports it, the generalized eigenvalue problem A⋅x = λ⋅B⋅x via gev

gev(l, A, B, nev; kwargs...) -> (values, vectors, converged, numops)

Both return the same four elements:

elementmeaning
valuesat most nev eigenvalues, ordered according to the solver's which
vectorsthe matching eigenvectors, see geteigenvector
convergedtrue if at least nev eigenpairs converged
numopsnumber of operator applications used by the backend

vectors is a matrix whose columns are the eigenvectors for all solvers except the matrix-free ones (see AbstractMFEigenSolver), which may return a vector of vectors. Use geteigenvector to access an eigenvector independently of the solver.
